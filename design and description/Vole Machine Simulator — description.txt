Vole Machine Simulator — Initial Design Description

1. System Overview

We want to design a Vole Machine Simulator using object-oriented design. The simulator should load programs from text files, execute their instructions whether line by line or one time run, and allow users to inspect the machine's memory, registers, and current execution state.

The system should support two execution modes:

Run mode: Execute the program continuously until it halts.

Step-by-step mode: Execute one instruction at a time and allow the user to continue by pressing Enter.

The system will contain six main classes: VoleMachine, CPU, Memory, Register, ALU, and UI.

2. Classes and Responsibilities

A. CPU

The CPU is responsible for fetching and executing program instructions. It maintains the program counter and the current instruction, and it uses the registers, memory, and ALU to perform operations.

Attributes:

Register reg: Represents the CPU's register collection so we can control them through this object.

ALU alu: Performs arithmetic, logical, and other instruction-related operations.

int pc: Program counter — the address of the next instruction to fetch.

string IR: Instruction Register — stores the currently fetched instruction.

Methods:

Constructor: Initializes pc to zero and IR to "0000", as IR should be 4 hexadecimal digits.

Fetch(): Fetches the instruction from memory using the current program counter and advances the PC by two memory addresses.

Execute(): Executes the current instruction. The CPU should interpret the instruction and coordinate with the ALU and registers as needed. The Execute method should perform the actual operations, such as addition, OR, and storing values.

The PC may need to be changed by jump instructions, and execution should stop when a halt instruction is encountered.

B. Memory

The Memory class represents the machine's main memory.

Attributes:

vector<string> memory: Stores the contents of memory.

Methods:

Constructor: Initializes 256 memory cells, with each cell containing "00", as each cell stores 8 bits.

get(address): Returns the value stored at a specified memory address.

set(address, value): Stores a value at a specified memory address.

Memory addresses range from 00 to FF. Each cell stores an 8-bit value represented by two hexadecimal digits.

The address FF is also used as a special screen output address. When a store instruction writes to this address, the value should be displayed on the screen.

C. Register

The Register class represents the CPU's general-purpose registers.

Attributes:

vector<string> registers: Stores the values of the registers.

Methods:

Constructor: Initializes 16 registers, each containing "00".

get(index): Returns the value of a specified register.

set(index, value): Updates the value of a specified register. The value should be hexadecimal.

The registers are named R0 through RF. Each register stores an 8-bit value represented by two hexadecimal digits.

D. ALU

The ALU class is responsible for supporting instruction operations and handling conversions between different representations.

Attributes:

vector<string> opCodes: Stores or represents the supported operation codes, covering the relevant instruction codes from 1 through C.

Methods:

Constructor: Initializes the supported operation codes.

hexToDec(): Converts a hexadecimal value to decimal.

decToHex(): Converts a decimal value to hexadecimal.

validOP(): Checks whether an operation code is valid.

hexToFloat(): Converts a hexadecimal representation into a floating-point value.

floatToHex(): Converts a floating-point value into a hexadecimal representation.

The ALU should support the arithmetic and logical operations required by the machine's instruction set so we can separate the actual work from auxiliary operations.

E. VoleMachine

The VoleMachine class represents the complete machine and coordinates its main components.

Attributes:

CPU cpu: The CPU responsible for instruction execution.

Memory mem: The machine's memory.

bool isOneByOne: Indicates whether the machine is running in step-by-step mode.

Methods:

setIsOneByOne(): Sets the execution mode.

LoadFile(): Loads a program from a text file into memory.

Execute(): Starts program execution according to the selected execution mode.

output(): Handles displaying output generated by the program.

Programs contain four-hexadecimal-digit instructions. Each instruction occupies two consecutive memory cells, so programs must be loaded starting at an even address, such as 00, 02, 04, and so on.

The file loader should ignore blank lines and semicolon comments. It should load valid instructions into memory in the appropriate format. For each line, only the first four hexadecimal digits should be taken as the instruction. If a line contains fewer than four characters, it is not a valid instruction.

F. UI

The UI class is responsible for interacting with the user.

Attributes:

VoleMachine machine: Represents the machine controlled through the interface.

Methods:

showMenu(): Displays the available menu options.

takeInput(): Reads and processes user input.

The UI should allow the user to load a program, choose the execution mode, modify register and memory values, and inspect the machine's state. It should display the memory as a matrix, along with the PC, IR, registers, and screen output as required.

After execution finishes, the UI should allow the user to exit or load another program.

3. Relationships Between Classes

UI interacts with VoleMachine to receive user commands and display results.

VoleMachine contains and coordinates the CPU and Memory.

CPU uses Register to access and modify register values.

CPU uses ALU to perform the operations required by instructions.

CPU accesses Memory to fetch instructions and perform memory-related operations.

VoleMachine controls the execution process and coordinates the selected execution mode.
